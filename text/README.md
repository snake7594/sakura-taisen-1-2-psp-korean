# 사쿠라대전 1&2 (PSP) — 번역용 텍스트 덤프

`tools/export_text.py`가 ISO에서 직접 생성합니다. 다시 만들려면:

```bash
python tools/export_text.py
```

## 파일

| 파일 | 행 수 | 내용 |
|---|---|---|
| `sakura1_adv.tsv` | 31,481 | 사쿠라 1 어드벤처 파트 — `ADVMACRO.PFS` 안의 `*tbl.bin` 58개 |
| `sakura1_slg.tsv` | 3,586 | 사쿠라 1 전투 파트 — `SLGMAP.PFS` 안의 `m##mes.bin` 26개 |
| `sakura2_adv.tsv` | 38,822 | 사쿠라 2 **본편 대사** — `SAKURA2/SAKURA1/SK####.CMP` 83개 |
| `sakura2_evt.tsv` | 12,773 | 사쿠라 2 이벤트·시스템 — `SAKURA2/SAKURA2/*.MES` 399개 |
| `unique_strings.tsv` | 45,421 | 위 4개의 **중복 제거본** |
| `gaiji_legend.png` | — | 외자 글리프 이미지 |

전체 86,662행 / 1,778,948자이지만, 중복을 빼면 **45,421행 / 1,043,741자**입니다.

사쿠라 2 본편 대사(`SK####.CMP`)는 `.CMP` 로 압축돼 있어 처음 조사에서 놓쳤다가
나중에 찾았습니다. 사쿠라 2 분량의 대부분이 여기 있습니다.

## 한 줄 길이 (실기 확인)

| 파일 | 한 줄 | 줄 수 |
|---|---|---|
| `sakura1_adv`, `sakura1_slg` | 21자 | 3줄 |
| `sakura2_adv`, `sakura2_evt` | **14자** | 3줄 |

PPSSPP 에서 자(ruler)를 넣어 잰 값입니다. 사쿠라 2 는 15번째 글자가 자동 줄바꿈에서
사라지므로 반드시 직접 `\n` 으로 끊어야 합니다.

## 작업 방식 (권장)

`unique_strings.tsv`의 `ko` 열만 채우면 됩니다. 나머지 4개 파일의 `flags` 열에
`dup=<key>`가 있는 행은 그 키의 번역을 그대로 쓰면 되므로 작업량이 줄어듭니다.
가장 많이 쓰이는 문자열부터 정렬돼 있습니다.

## 열 설명

| 열 | 의미 |
|---|---|
| `key` | 고유 식별자. `S1A:0100tbl:12` = 사쿠라1 ADV / `0100tbl.bin` / 12번 엔트리 |
| `file` | 원본 멤버·파일명 |
| `index` | 그 파일 안에서의 엔트리 번호 |
| `id` | 엔트리 ID (사쿠라 1) 또는 4바이트 엔트리 헤더 (사쿠라 2, 화자·음성 ID로 추정) |
| `flags` | `dup=<key>` 같은 문자열이 앞서 나옴 / `gaiji=XXXX` 외자 사용 |
| `ja` | 원문 |
| `ko` | **여기에 번역을 넣으세요** (비어 있음) |

### 이스케이프

TSV 한 행 = 문자열 하나를 유지하기 위해 원문 안의 제어문자를 치환했습니다.

- `\n` — 줄바꿈 (사쿠라 1은 원본에서 `$$`, 사쿠라 2는 `0xFFFE`)
- `\t` — 탭, `\\` — 역슬래시 자체
- `<XX>` / `<XXXX>` — 게임 제어 코드. **그대로, 같은 순서로 두세요.**
  사쿠라 1 쪽에는 없지만 `sakura2_adv.tsv` 에 **1,591개(38종)** 있습니다.
  `<FFFC><000X>` 는 문장 맨 앞, `<FFFA><00XX>` 와 `<FFFD>` 는 맨 뒤에 오는 것이 보통이고,
  `<FFFA>` `<FFFB>` `<FFFC>` 뒤의 `<00XX>` 는 딸린 인자라 둘을 한 덩어리로 다뤄야 합니다.

## 외자 (gaiji) 주의

폰트가 해당 Shift-JIS 자리에 표준 문자가 아닌 **다른 글리프**를 그립니다.
`ja` 열에는 실제로 화면에 보이는 문자를 넣었고, `flags`에 원래 코드를 남겼습니다.
글리프 모양은 `gaiji_legend.png`를 보세요.

| SJIS | 실제 표시 | 사쿠라 1 | 사쿠라 2 |
|---|---|---|---|
| `81AC` | ⁉ | 973 | 897 |
| `81B8` | ‼ | 1765 | 1073 |
| `81BF` | 翔 | (미사용) | 39 |
| `81CE` | {81CE} 미확인 | (미사용) | 1 |
| `81DC` | 冑 | (미사용) | 63 |
| `81E5` | 璧 | (미사용) | 12 |

폰트에는 외자 자리가 더 있습니다 — 사쿠라 1은 `81B9`~`81BE`(マザーグース),
사쿠라 2는 추가로 `81C8`~`81CE`, `81DA`~`81E6`(甦戮鬪慟哭擲爛邂逅檄渕澤條濱廣繚瞞炸 등
옛 한자). 다만 **실제 스크립트에서는 위 표의 5개만 쓰입니다.** 만약 미확인 외자가
나오면 `{XXXX}` 형태로 표기되니 추측 없이 그대로 두세요.

## 원본 포맷 (재삽입용)

**사쿠라 1** `*tbl.bin` (`.PFS` = `PAKFILE` 아카이브 안)
```
u16BE 테이블워드수 (÷2 = 엔트리 수) | u16BE ?
엔트리 × { u16BE id, u16BE offset }      ← offset은 16비트 워드 단위
텍스트: 빅엔디안 Shift-JIS, NUL 종료, "$$" = 줄바꿈
```

**사쿠라 2 본편** `SK####.CMP` (`.CMP` 압축)
```
풀면  u32LE 헤더 [2]=인덱스 테이블 오프셋  [3]=텍스트 블록 오프셋  [4]=전체 크기
      인덱스: u32LE, 텍스트 블록 기준 16비트 단위 오프셋
      텍스트: .MES 와 같은 규칙
```

**사쿠라 2 이벤트** `*.MES`
```
u32BE count | count × u32BE 절대 오프셋
엔트리 = 4바이트 헤더 + 텍스트
텍스트는 16비트 리틀엔디안 단위에 Shift-JIS 쌍   ← 바이트 순서가 뒤집혀 있음
0xFFFE = 줄바꿈, 0xFFFF = 메시지 끝
```
`EV*.MES`는 메시지 뒤에 립싱크 데이터가 붙어 있습니다. 재삽입 시 건드리면 안 됩니다.
